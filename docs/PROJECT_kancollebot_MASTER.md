# KancolleBot 项目规则与架构

## 目标

构建一个运行在用户本地 Windows/POI 环境中的舰队收藏自动化 Bot。GitHub 用于代码托管、审查与自动测试，不承担持续运行游戏客户端的职责。

## 架构原则

1. 优先读取 POI 提供的、经过源码或运行时证据验证的数据接口。
2. 先建立状态模型、适配器契约和模拟测试，再实现游戏操作。
3. 自动远征优先；自动战斗在远征模块和安全层通过验证后再推进。
4. Python 为主要实现语言；能用标准库解决时不引入第三方依赖。
5. KCA/kcauto_custom 是主要行为研究参考；POI、KCA、KLL 和 KCPS 是独立项目，不将它们错误描述为依赖关系。
6. 将已证实事实、推断和待验证事项分开记录，技术结论尽可能附源文件、行号、调用链或测试证据。

## 安全边界

- 默认禁止真实游戏操作；初始代码仅定义安全门，不连接 POI、不发出操作请求。
- 不公开 POI 调试端口，不将本地调试服务绑定到公网。
- 不提交账号密码、Cookie、令牌、API 密钥、个人游戏会话数据或不必要的请求内容。
- 不复制或上传完整的 POI/KCA/KLL 第三方源代码树；仅保存必要的研究笔记、引用和可验证证据。
- 不因测试通过就宣称功能已在真实游戏中验证。
- 新依赖、付费 API、付费服务或本地软件安装必须先说明成本/收益并取得用户明确同意。
- 真实游戏操作须在接口验证、模拟测试、失败恢复与停止机制验证后分阶段启用。

## 质量门槛

- 每个模块具有独立测试。
- 状态数据经过输入校验。
- 任何未来的操作适配器必须具备前置条件检查、明确停止方式和审计日志。
- CI 通过仅代表当前自动检查通过，不代表游戏行为正确或可安全运行。
